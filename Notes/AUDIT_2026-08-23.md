# Crooked Galaxy — living audit (refreshed 2026-08-24)

## Reference boundaries

The local Shakes & Fidget material remains study-only under `References/` and is excluded from Godot imports. Crooked Galaxy does not reuse its proprietary code, formulas, names, text, protocols, interface, or assets.

The useful general observations remain limited to product principles: repeatable loot needs legible comparison, long progression benefits from stable collections and feature hubs, and large catalogs benefit from reusable visual/data boundaries. Crooked Galaxy implements these ideas independently through original rules, content, procedural presentation, stable IDs, and deterministic validation.

## Current product state

- The complete bounty loop is playable: board, approach, timed hunt, incident, automatic combat, reward, loot decision, workshop, and stronger contracts.
- Four four-target chapters provide sixteen original wanted targets, eight planet-specific incidents, bosses, equipment families, progression, and persistent travel.
- Repeat motivation includes capture streaks, three mastery tiers per target, improved loot quality, career milestones, AFK patrol rewards, and a persistent wanted archive that recommends the closest unfinished mastery tier.
- Loot supports rarity, four combat-relevant modifications, planet of origin, and a two-piece planetary kit bonus. Item comparison evaluates the complete build rather than raw power alone.
- The arsenal provides filters, sorting, explicit tradeoffs, item protection, two loadouts, safe bulk recycling, power calibration, and capped integrity reinforcement with partial investment recovery.
- The arsenal's field test translates both workshop paths into projected odds against the next warrant before the player spends scrap.
- Mobile presentation uses safe areas, large touch targets, vertical inventory scrolling, procedural portraits/backdrops, and runtime-synthesized audio.

## Engineering state

- `game_state.gd` owns the phase machine and persisted transactions; deterministic rules are isolated in focused modules.
- `ui_factory.gd` owns shared presentation primitives; `arsenal_view.gd`, `reward_view.gd`, and `career_view.gd` own the complete inventory/workshop, loot-decision, and career/archive renderers.
- Saves use explicit incremental migrations and preserve interrupted briefing, hunt, combat, reward, chapter, loadout, and workshop state.
- `tools/check_project.ps1` runs fifteen deterministic suites and a clean boot. Each run now uses isolated log files, while persistence tests use unique workspace-local saves so open Godot instances cannot corrupt test results.
- Balance simulation executes the same damage helpers as runtime combat and verifies displayed odds against 5,000-fight samples.
- Automated captures cover the main loop, reward decisions, career/archive, arsenal, galaxy, incidents, and all chapter finales.

## Findings addressed during this audit

1. Equipment modifications existed, but the two slots still behaved mostly as isolated stat containers. New opening-shot and incoming-damage traits now create distinct tactical identities.
2. Loot origin was flavor-only. Every newly generated item now records its planet, and matching weapon plus armor activates an explicit `+1 power / +6 health` planetary kit.
3. Raw item comparison could discard a weaker-looking piece that improved the complete build. Reward recycling, bulk recycling, upgrade labels, combat odds, and simulator decisions now evaluate the equipped build and its kit transition.
4. The 450×800 arsenal capture exposed horizontal clipping and a collapsed inventory area. Workshop and loadout cards were compacted, sorting received its own row, item comparisons moved into the flexible details column, and mobile tests now enforce horizontal bounds plus useful inventory height.
5. Concurrent Godot instances shared default logs and fixed test saves. The checker and persistence suite now isolate both resources per process.
6. Early planet progression was visible only beneath the contract list, and repeating a threshold capture could bypass the newly unlocked warrant. The next-target objective now sits above the board, reward screens preview exact capture progress, and threshold rewards route the first visit back to the expanded board with the new target named explicitly.
7. Automatic combat exposed only the latest exchange, so players could not tell what their build contributed. Combat now accumulates exact turns, damage dealt/received, criticals, mitigation, opening bonus, and active kit; victory shows a compact report, while defeat keeps a red diagnostic on the board with the target's remaining health. Round state is saved as it advances so this evidence also survives interruption.
8. Reward rendering had become a dense branch inside the main phase controller. It now lives in `reward_view.gd` with explicit state/host dependencies and isolated coverage for normal repetition, threshold unlock routing, board return, and safe instant recycling; `main.gd` is back near one thousand lines.
9. Workshop buttons exposed prices and raw stat gains but not their practical value. The arsenal now compares current, `+1 power`, and `+8 health` builds against the next warrant. Same-target projections share a deterministic combat roll stream, so genuine upgrades cannot appear worse because of Monte Carlo noise; the 5,000-fight simulator remains aligned with displayed odds.
10. The wanted archive documented mastery but did not convert it into a next action. Career rules now select the closest unfinished mastery tier, the screen explains the next rare/epic loot bonus, and a direct action returns to that target's planet. The touched renderer moved from `main.gd` into `career_view.gd` with isolated coverage.
