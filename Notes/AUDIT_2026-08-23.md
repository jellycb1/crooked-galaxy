# Crooked Galaxy — audit snapshot (2026-08-23)

## Reference boundaries and useful principles

The local Shakes & Fidget material remains study-only and outside Godot imports. No proprietary code, formulas, names, text, protocols, UI, or assets are used by Crooked Galaxy.

The useful high-level observations are:

- large item, portrait, and enemy catalogs benefit from stable categories and reusable presentation;
- achievements work best as persistent goals with visible completion and collection states;
- locations and feature hubs keep long-lived progression readable;
- shared visual/audio building blocks reduce the cost of adding content.

Crooked Galaxy already follows these principles independently through stable IDs, planet item families, procedural portraits, synthesized audio, planet chapters, and content validation. This audit extends them with an original claimable career system and wanted archive.

## Current strengths

- The complete bounty loop is playable: selection, approach, timed hunt, incident, automatic combat, reward, loot, equipment, and stronger contracts.
- Three chapters have distinct targets, bosses, incidents, equipment families, visual themes, and persistent travel progression.
- AFK progress, interrupted hunts, combat, rewards, preferences, inventory, and chapter state persist locally.
- Deterministic tests cover rules, flow, persistence, UI, audio, and content integrity.
- Screenshot and balance tools make visual and economy regressions observable.
- Original procedural presentation provides a clean replacement boundary for future final art.

## Findings addressed in this batch

1. Career progression was passive. Completed milestones offered no reward, the board did not signal pending career actions, and target portraits had no persistent collection surface.
2. Displayed combat odds used a coarse logistic approximation. Balance simulation exposed significant mismatches in several risk/reward choices.

Implemented corrections:

- five milestones now have stable IDs, claimable credit/scrap rewards, lifetime totals, persistence, and duplicate-claim protection;
- the bounty board shows the number of career rewards awaiting collection;
- the career view includes a twelve-target wanted archive with captured, available, and classified states;
- combat odds now use a seeded deterministic simulation of the same alternating combat rules shown to the player;
- automated UI capture now includes the wanted archive.

## Remaining priorities

1. Improve the loot-to-upgrade loop with inventory sorting, comparison, and multi-item recycling; this is the largest recurring friction in the central product test.
2. Introduce an explicit save migration pipeline before the save schema grows beyond additive fields.
3. Split the large interface script by feature when the next major screen is added; current behavior is stable, but continued growth in one file will slow iteration.
4. Add mobile safe-area, touch-target, and low-resolution checks before export work begins.
5. Add a fourth chapter only after the repeatable loot and equipment decisions become deeper; more content should amplify a strong loop rather than mask friction.

## Autonomous follow-up

The first two engineering priorities were addressed immediately after this snapshot:

- the arsenal now provides slot filters, power/rarity sorting, explicit comparisons, salvage previews, and safe multi-item recycling that preserves equipped items and upgrades;
- saves now use an explicit version constant and incremental version 1 → 2 migration path with legacy-save coverage.
- rare and epic loot can now roll independently designed equipment modifications; effective comparison accounts for combat power and integrity, and bulk recycling preserves mechanically superior modified gear.

The next product priority is validating the new equipment decisions through longer progression runs, then considering saved loadouts or a fourth planet rather than adding more inventory administration.
